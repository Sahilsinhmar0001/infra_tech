# InfraTech Solutions

An IT infrastructure services website with a Next.js frontend, an Express API, and PostgreSQL. The root `docker-compose.yml` runs all three services for local development.

## Run Locally

Install dependencies in all packages from the workspace root:

```bash
npm run install:all
npm run dev
```

The website is available at `http://localhost:3000`, the API at `http://localhost:5000`, and PostgreSQL at `localhost:5432`. The backend needs a valid `DATABASE_URL`; set email delivery through `EMAIL_USER` and `EMAIL_PASS`. Keep credentials in local environment files and out of source control.

To run the stack with Docker, use `docker compose up --build`. The compose file enables file polling for development mounts and provisions a PostgreSQL container.

## Application Structure

### Frontend

The frontend uses the Next.js App Router. `src/app/layout.tsx` provides the shared navigation, footer, fonts, and metadata; `src/app/globals.css` defines the Tailwind CSS entry point and base colors.

Route files are:

- `src/app/page.tsx`: home page and service summary.
- `src/app/about/page.tsx`: company story and values.
- `src/app/services/page.tsx`: service catalogue and delivery process.
- `src/app/projects/page.tsx`: project portfolio; remote Unsplash images use Next Image optimization.
- `src/app/contact/page.tsx`: interactive contact form that posts to the backend.
- `src/app/admin/page.tsx`: client-rendered message dashboard that reads contact submissions.
- `src/components/Navbar.tsx`: shared responsive navigation and mobile menu.
- `src/components/Footer.tsx`: shared footer and site links.

The home, about, services, and projects routes are Server Components because their content does not require browser state. Contact and admin remain Client Components because they use state and browser-side requests.

### Backend

- `backend/src/index.ts`: Express setup, security/CORS middleware, PostgreSQL/Prisma connection, health endpoint, and contact submission/list endpoints.
- `backend/prisma/schema.prisma`: PostgreSQL models and enums. `ContactMessage` backs the contact form; `User` and `Role` are schema definitions but are not currently used by an authentication flow.
- `backend/prisma.config.ts`: Prisma CLI schema and database URL configuration.

The contact API is `POST /api/contact`; `GET /api/contact` returns stored submissions. `GET /api/health` is a basic liveness check.

## File Guide

- Root `package.json` starts both development servers and installs the three package trees; root `package-lock.json` locks the root tools.
- `docker-compose.yml` describes the frontend, backend, and database development services.
- Each package's `package.json` defines its dependencies and scripts; each `package-lock.json` pins its dependency tree.
- `frontend/next.config.ts` configures Next.js, including the allowed remote image host.
- `frontend/postcss.config.mjs` connects Tailwind CSS to PostCSS; `frontend/eslint.config.mjs` configures lint rules.
- `frontend/tsconfig.json` configures TypeScript and the `@/*` source alias; `frontend/next-env.d.ts` is generated by Next.js.
- `backend/tsconfig.json` configures TypeScript compilation; `backend/Dockerfile.dev` and `frontend/Dockerfile.dev` build the development containers.
- `.dockerignore` files exclude local-only files from Docker build contexts; `.gitignore` files exclude generated or local files from version control.
- `frontend/AGENTS.md` and `frontend/CLAUDE.md` are editor/agent guidance, not application runtime code.
- `backend/.env` is local configuration only. Never commit it or put real secrets in the README.

## Checks

Run frontend lint/build from `frontend/`:

```bash
npm run lint
npm run build
```

Run backend type-check/build from `backend/` with `npm run build`. The backend currently has no automated test suite (`npm test` is a placeholder).

## Production Readiness

The `/admin` page and `GET /api/contact` endpoint currently have no authentication or authorization. Do not expose them to the public internet until an admin authentication flow and API authorization are implemented. Also configure production CORS, validate contact payloads server-side, and provide production email/database settings through secrets management.
